# Automatic mail archiving / 自动归档新邮件

Reviewed **2026-11-09**. All linked sources were accessed that day. This is official-document research and an engineering recommendation, **not an executed account connection or a claim that MailCairn sync already works**. No mailbox, credential, subscription, or provider setting was changed. Existing single-message Proton export tests do not validate synchronization.

核查日期 **2026-11-09**。链接均于当日访问。本页是官方资料核查和工程建议，**不是已连接账号或已完成自动同步的声明**；没有更改邮箱、凭据、订阅或提供商设置。此前 Proton 单封导出实测不能证明同步可用。

## Concrete choice / 具体选择

Implement **local, one-way incremental archiving**: connect once, copy new mail automatically while the desktop worker runs, retain archived bytes even if the source later deletes them. Keep file import for initial migration and recovery. First deliver a real read-only IMAP connector for ordinary IMAP accounts, eligible Gmail app-password accounts, and paid Proton Bridge. For a broadly distributed Gmail experience, add a MailCairn-owned desktop OAuth client using Gmail API `gmail.readonly`; do not present an unconfigured OAuth button as a working connector. Proton Free remains unsupported for continuous ingestion until a supported access route is established.

实施**本机单向增量归档**：一次连接后，桌面后台进程自动复制新邮件；云端后续删除不删除已归档内容。文件导入保留用于迁移和恢复。首个可交付连接器采用只读 IMAP，覆盖普通 IMAP、可创建应用密码的 Gmail 和付费 Proton Bridge。面向普通 Gmail 用户发布时，再提供 MailCairn 自有桌面 OAuth 客户端及 `gmail.readonly` API；没有真实授权配置时不能把按钮称作可用功能。Proton 免费账号的持续接入暂不承诺。

This choice follows the user's new requirement and avoids repeated export work. It is not new evidence of market demand or willingness to pay; [earlier market research](market-research.md) already recorded a user succeeding with OpenArchiver.

这项选择来自用户明确提出的免重复导出需求，不构成新的市场或付费验证；[既有研究](market-research.md)已记录用户用 OpenArchiver 解决相近问题。

**Initial implementation scope agreed after research:** only **INBOX**, checked every **five minutes while the desktop app is open**, with manual Sync now and pause/disconnect controls. This does not capture sent mail, other folders, or mail moved out of INBOX before the next check; it does not promise background operation after quitting. The connector is one-way and must not delete source mail or change read flags. Folder selection and broader background scheduling below are later design requirements, not current capabilities. Historical export instructions remain valid for manual imports; they do not describe the new automatic path.

**研究后确定的首版范围：** 仅 **INBOX 收件箱**，**桌面应用开启时每 5 分钟**检查，提供立即同步、暂停和断开。不涵盖已发送或其他文件夹，也无法保证捕获检查前已移出收件箱的邮件；退出后不承诺后台运行。只能单向归档，不删除源邮件、不更改已读标记。下文文件夹选择及更完整后台调度是后续设计要求，不是当前已实现能力。既有导出指南保留为手动导入的历史流程说明。

Treat direct REST integration as a separate research project, not a promised free Bridge replacement. The free [Export Tool](https://proton.me/support/proton-mail-export-tool) is a backup/export workflow; its documented interface does not establish unattended incremental sync.

## What makes the connector complete / 完整交付要求

The following is the proposed implementation contract, not a provider claim:

1. **One-time setup:** choose account type, authorize or enter its supported credential, test the connection, choose folders and initial history scope. Show unsupported account conditions before promising sync. Store secrets in the operating system credential facility, separate from archive backups.
2. **One-way reads:** IMAP `EXAMINE` and `BODY.PEEK[]`; no `STORE`, `EXPUNGE`, delete, move or send operation. Track account + mailbox + `UIDVALIDITY` + UID, not sequence numbers. Commit original bytes and progress together; on UIDVALIDITY change rescan safely. Keep failed items retryable so a later high-water mark never silently skips them. These protocol choices follow [IMAP RFC 9051](https://www.rfc-editor.org/rfc/rfc9051.html); the archive retention policy is our choice.
3. **Automatic lifecycle:** an explicit enabled/paused state, scheduled polling while the worker runs, reconnect/backoff, catch-up after sleep, last successful sync and next attempt. Closing the reader must not silently stop an enabled worker; quitting the worker must make the stop clear. A powered-off computer cannot capture mail deleted before its next connection.
4. **Gmail API version:** first enumerate/download the selected scope, then persist `historyId` and request changes. An expired history cursor can return 404 and requires full reconciliation. Preserve local mail when deletion events arrive. Avoid introducing hosted push infrastructure for the first desktop version. [Google sync guide](https://developers.google.com/workspace/gmail/api/guides/sync)
5. **Acceptance before claiming “working”:** with an authorized test account, observe a new message arriving without export; repeat a cycle without duplicates; restart and resume; simulate disconnect and revoked credentials; preserve source unread state; verify raw/attachment bytes; confirm local retention after authorized source deletion; back up/restore and reconnect without data loss. Test UIDVALIDITY changes and failed-record retries synthetically. No provider connection was executed in this research task.

以上是实现约定：一次设置账号、范围和凭据；只读抓取，不改已读、不移动或删除；按账号／文件夹／UIDVALIDITY／UID 持久记录进度并保留失败重试；后台定时运行、休眠后补拉、明确暂停与错误；Gmail 历史游标失效时重新核对。真正验收需观察新邮件自动进入、重启续传、重复周期不重复、原始字节和附件一致，并验证源端删除后本地仍保留。关闭网页不应悄悄停止后台，电脑关机期间已被删除的邮件无法保证补回。本研究没有执行这些账号测试。
